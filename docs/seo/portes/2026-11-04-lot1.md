## Données structurées : un défaut, hors blog

`check-donnees-structurees.mjs` : 292 nœuds sur 26 pages, **2 défauts sur la même page** :

- `/outils/quel-salaire-pour-un-loyer` → `WebApplication` sans `offers` ;
- même page → `WebApplication` sans `aggregateRating` ni `review`.

Google exige les trois ensemble pour ce type ; sans eux, l'élément est signalé invalide dans la Search
Console et n'ouvre aucun résultat enrichi. Rien n'est cassé à l'indexation. Correction à la charge de
`seo-outils` : un avis ou une note ne s'inventent pas, donc **retirer le bloc `WebApplication`** (et
garder `WebPage` ou le fil d'Ariane), plutôt que de le compléter. `offers` à 0 € seul ne suffirait pas.

## La nav (faite dans ce lot, non commitée)

Fichier de plus : `components/layout/NavClient.tsx`. Pourquoi : `Nav.tsx` était un composant client ;
y lire `blogOuvert()` aurait importé `lib/blog`, donc les fiches de tous les articles, dans le JavaScript
de chaque page. Désormais :

- `Nav.tsx` est un composant serveur de quelques lignes : il calcule `lienBlog()` et rend `NavClient`.
- `NavClient.tsx` porte le code client d'avant, à l'identique, avec une prop `blog` : le lien « Le blog »
  s'ajoute à la colonne « Les guides » du menu mobile quand le blog est ouvert.
- La barre de bureau garde ses quatre destinations (sa place relève du pôle Design).
- Les 11 fichiers qui importent `Nav` sont tous des composants serveur ; aucun appel n'a changé.
  `npx tsc --noEmit` propre. Pas de build.

Ce changement n'est pas dans `c174eb8` : il passera par la porte suivante.
